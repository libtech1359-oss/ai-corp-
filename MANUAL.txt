  1. システム概要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PC常時稼働のDiscord botで、投資判断を補助するマルチエージェントAIシステム。
  外出先からスマホで指示を出せる。

  【全体像】
  CEO（あなた）
    ├─ Discord #ai秘書    ← テキストで指示を出す
    ├─ Discord #ai-観測   ← AI組織の思考をリアルタイムで観察
    └─ /dashboard        ← 一瞬で全体状況を把握

  AI組織（secretary.js が統括）
    ├─ マーケット分析部
    ├─ ポートフォリオ管理部
    ├─ リスク管理部
    ├─ 反対意見部（Devil's Advocate）
    ├─ 監査部
    ├─ publisher（外部公開用整形）   ← 分析 ≠ 公開 を分離
    └─ trader（仮想売買提案）        ← 監査承認時のみ発動

  成果物の流れ
    分析完了
      ↓
      ├─ Discord に最終レポート
      ├─ reports/{type}/YYYY-MM-DD.md        ← 内部保存
      ├─ reports/{type}/public/*_note.md     ← note.com用
      ├─ reports/{type}/public/*_x.txt       ← X投稿用
      ├─ data/shadow_book.json               ← 仮想売買記録
      └─ GitHub に自動push → Pages で公開

  【使用技術】
  - Node.js + discord.js v14
  - Ollama（ローカルLLM: gemma4）
  - Google Apps Script（スプレッドシートからデータ取得）
  - SQLite（長期記憶: memory.db）
  - node-cron（定時実行）
  - GitHub Pages（公開ダッシュボード）

  2. 起動・停止方法
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【自動起動】
  PC起動時に自動スタートする設定済み。
  スタートアップ経由: start_ai_secretary.bat → VBScript

  【手動起動】
  D:\AI\ai-corp> node index.js

  【手動停止】
  ターミナルで Ctrl+C

  【再起動が必要なタイミング】
  - index.js / secretary.js / agents/*.js / scheduler.js を変更したとき
  - .env を変更したとき
  - node_modules を更新したとき（npm install後）

  【コマンド再登録が必要なタイミング】
  スラッシュコマンドを追加・変更したとき:
  D:\AI\ai-corp> node register.js
  （その後 bot を再起動）

  3. AI部署構成（エージェント）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌──────────────────┬───────────────────────────────────────────────────┐
  │ 部署名           │ 役割                                              │
  ├──────────────────┼───────────────────────────────────────────────────┤
  │ 秘書室長         │ タスク分解・全部署への指示・最終統合              │
  │ マーケット分析部 │ 指数・為替・コモディティ・暗号資産の動向分析      │
  │ ポートフォリオ   │ 保有銘柄評価・アロケーション・NISA活用            │
  │ リスク管理部     │ VIX・ドローダウン・集中リスクの定量評価          │
  │ 反対意見部       │ 他3部署の楽観分析に意図的に反論・最悪シナリオ    │
  │ 監査部           │ 6項目審査（方針違反/幻覚/矛盾/数値/履歴/過信）   │
  │ publisher        │ 分析→公開用に変換（note/X整形・投資助言除去）    │
  │ trader           │ 監査承認後に仮想売買提案を1件生成                │
  └──────────────────┴───────────────────────────────────────────────────┘

  【publisher の設計思想】
  market/risk/devil/audit の内部分析 ≠ 外部公開コンテンツ。
  publisherが間に入り、「AIが分析した」という第三者視点に変換する。
  「〜を推奨します」などの投資助言表現はシステムプロンプトレベルで禁止。

  【trader の発動条件】
  audit の verdict が「承認」または「条件付き承認」のときのみ実行。
  「要見直し」のときは記録しない（これが重要）。
  実注文は行わない。data/shadow_book.json への記録のみ。

  【新部署の追加方法】
  1. agents/ フォルダに新ファイルを作成（analyze(context) を実装）
  2. secretary.js の AGENTS 配列に require('./agents/新部署') を追加
  3. DEPT_KEY に日本語名→キー名のマッピングを追加
  ※ これだけで自動的にパイプラインに組み込まれる

  4. 分析パイプライン
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CEO指示（または スケジューラー自動起動）
    ↓ task_id 採番（例: task-20260601-001）
    ↓ #ai-観測 に「処理開始」を投稿
  Step 1: GASデータ取得 + 長期記憶参照
    ↓ #ai-観測 に「データ取得完了」
  Step 2: 秘書がブリーフィング文生成（300字以内）
    ↓ #ai-観測 に「タスク分解完了」
  Step 3: 市場/ポートフォリオ/リスク 並列分析
    ↓ 各完了時に #ai-観測 に投稿（到着順でリアルタイム表示）
  Step 3.5: 反対意見部（3部署レポートを見てから反論）
    ↓ #ai-観測 に投稿
  Step 4: 監査部 6項目審査 → 承認/条件付き承認/要見直し
    ↓ #ai-観測 に判定結果を投稿
  Step 5: 最終統合レポート生成
    ↓ #ai秘書 に返信
    ↓（スケジューラー実行時のみ）
  Step 6: レポートファイル保存（reports/）
    ↓
  Step 7: publisher でnote/X用に変換・保存
    ↓
  Step 8: GitHub に自動push
    ↓
  Step 9: audit承認時 → trader が仮想売買提案 → shadow_book に記録

  【タスクドキュメント】
  各ステップの結果が data/tasks/task-YYYYMMDD-NNN.json に逐次書き込まれる。
  途中でクラッシュしても完了済みステップのデータは残る。

  5. Discordコマンド一覧
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【最重要】
  /dashboard       🏢 CEOダッシュボード
                   システム状態・リスクレベル・最新監査・Shadow Trade・
                   推奨アクション・監査コメントを1画面に集約。
                   AIが増えてもここを見るだけで全体把握できる。

  【マーケット・投資】
  /market          現在の市場データ（NASDAQ/S&P500/ゴールド/BTC/F&G）
  /portfolio       ポートフォリオ概要（評価額・含み益・収益率）
  /trades          直近の取引履歴（口座絞り込み可）
  /buy             ATH比較と買い判断（-30%以上:強い買い 〜 0%以上:最高値圏）
  /nisa            特定口座からNISA移行候補を表示
  /rules           投資ルール確認（現金残高を入力して余剰計算）

  【Shadow Trade】
  /shadow          仮想売買の記録・成績を表示
                   買い/売り/様子見 の件数・仮想買付合計・直近5件

  【記憶・プロファイル】
  /profile show    CEOプロファイル（構造化方針）を表示
  /profile set     プロファイル項目を設定（リスク許容度/VIX上限/F&G買いゾーン等）
  /remember        方針・ルール・メモを長期記憶（SQLite）に保存
  /memory          長期記憶の一覧表示
  /forget          長期記憶から特定IDを削除

  【ログ・履歴】
  /log             AI秘書のセッションログを参照
                   ステップ指定: summary / data / decompose / market /
                                 portfolio / risk / audit / report
                   日付指定: 例 2026-06-01
                   番号指定: 今日の何番目か（省略で最新）

  【システム管理】
  /halt            緊急停止（即時・確認なし）
  /resume          自動取引再開（確認ボタンあり・30秒タイムアウト）
  /status          現在のシステム状態表示
  /events          halt/resume/audit_override のイベント履歴

  【AI秘書（テキスト）】
  #ai秘書チャンネルに日本語で話しかける
  例:「今日の市場どう？」「ポートフォリオ全体の状況を教えて」
  → 全部署が並列分析 → 最終レポートが #ai秘書 に返る
  → 思考過程が #ai-観測 にリアルタイムで流れる

  6. スケジューラー（自律実行）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  bot起動と同時にスケジューラーも起動する。

  【定時実行】
  07:00 JST（月〜金）  朝の市場分析              → reports/morning/ に保存
  12:00 JST（月〜金）  昼のポートフォリオ確認     → ファイル保存なし
  15:30 JST（月〜金）  引け後レポート             → reports/close/ に保存
  16:00 JST（金のみ）  週次レポート               → reports/weekly/ に保存

  【イベント監視】
  5分ごとにNASDAQをチェック。
  前日比 -3.0% 以下を検知したら緊急監査を自動実行（1日1回）。

  【停止中の動作】
  system_state.json の trading_enabled が false のとき:
  → 定時実行・急落監視ともにスキップ（ログに「スキップ（停止中）」と記録）

  【スケジュール変更方法】
  scheduler.js の SCHEDULES 配列を編集してbotを再起動。
  reportType フィールドを設定するとレポートファイルが自動生成される:
    { name: '例', icon: '🌙', cron: '0 20 * * 1-5',
      instruction: '...', reportType: 'close' }

  【NASDAQ急落閾値の変更】
  .env に追記: CRASH_THRESHOLD=-5.0   ← -5%に変更する場合

  7. 自動レポート生成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  スケジューラー実行後、以下のファイルが自動生成される。

  【内部レポート】  reports/{type}/YYYY-MM-DD.md
  market/risk/devil/audit の生の分析内容をまとめたもの。

  【公開用レポート】 reports/{type}/public/YYYY-MM-DD_note.md
  publisherが内部レポートを変換したnote.com用記事。
  投資助言表現を除去し「AIが分析した記録」として書き直す。

  【X投稿用】       reports/{type}/public/YYYY-MM-DD_x.txt
  140文字以内に圧縮したX（旧Twitter）投稿文。
  Discordにもそのまま表示される。

  【Discordへの通知】
  スケジューラー完了後、#ai秘書 に以下が投稿される:
  📄 内部レポート → `reports/morning/2026-06-01.md`
  📝 note用 → `reports/morning/public/2026-06-01_note.md`
  🐦 X用: （140文字の投稿文）

  【GitHub Pages での確認】
  https://libtech1359-oss.github.io/ai-corp-/
  レポートが push されると自動的に表示される。

  8. 観測モード（#ai-観測）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  AI組織の思考過程をリアルタイムで観察する専用チャンネル。
  #ai秘書 には最終レポートだけ届く。#ai-観測 には中間過程が流れる。

  【流れる情報の例】
  ⏳ task-20260601-001 処理開始
    > 朝の定期市場分析…
  📡 データ取得完了 (2.1s)
  📋 タスク分解完了 (1.3s)
    > NASDAQは前日比-0.8%…
  📊 マーケット分析部 (4.5s)
    NASDAQ弱含み。前日比-0.8%…
  ⚠️ リスク管理部 (3.8s)        ← 並列のため到着順は変わる
  💼 ポートフォリオ管理部 (3.2s)
  🔴 反対意見部 (2.9s)
    楽観論への反論：…
  🔍 監査部 (2.1s) → 判定: 条件付き承認
  ✅ task-20260601-001 全エージェント完了
  ────────────────────────────────────

  【設定】
  .env に OBSERVE_CHANNEL=ai-観測 が設定済み。
  Discordサーバーに #ai-観測 チャンネルを作成するだけで有効になる。

  9. Shadow Trade（仮想売買記録）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  実注文を行う前に「AIが何を推奨したか」を記録し続けるシステム。

  【なぜ重要か】
  AIの分析精度より「継続運用」が難しい。
  Shadow Tradeを数ヶ月積み上げると「このAIの推奨に従うと何%取れたか」が
  客観的に見えてくる。実投資の判断材料になる。

  【発動条件】
  audit verdict = 承認 または 条件付き承認 のときのみ記録。
  「要見直し」のときは記録しない。

  【記録内容】（data/shadow_book.json）
  {
    "id":          "shadow-2026-06-01-001",
    "taskId":      "task-20260601-001",
    "date":        "2026-06-01",
    "action":      "buy",              ← buy / sell / hold
    "fund":        "eMAXIS Slim 米国株式",
    "amount_yen":  100000,
    "reason":      "NASDAQ回復基調、audit承認",
    "verdict":     "条件付き承認"
  }

  【Discord通知例】
  📋 Shadow Trade shadow-2026-06-01-001
  🟢 買い | eMAXIS Slim 米国株式 | ¥100,000
  > NASDAQ回復基調、audit承認

  【成績確認】
  /shadow コマンドで集計サマリー＋直近5件を表示。

  11. 緊急停止スイッチ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  system_state.json の trading_enabled が唯一の真実。

  【停止方法 3通り】
  (1) Discord: /halt コマンド（最速・推奨）
  (2) ファイル直接編集: trading_enabled を false に書き換え→保存
  (3) bot停止: node プロセスを Ctrl+C で終了

  【再開方法】
  (1) Discord: /resume → 確認ボタンを押す
  (2) ファイル直接編集: trading_enabled を true に書き換え→保存

  【安全設計】
  ・デフォルト: false（インストール直後から停止状態）
  ・ファイルが存在しない → false（停止）にフォールバック
  ・どんな異常時も必ず停止側に倒れる設計

  【halt_reason の種類】
  manual_stop     : /halt コマンドまたは手動
  crash_detected  : NASDAQ急落モニター
  audit_override  : 監査部による強制停止

  【イベント履歴の確認】
  data/event_log.jsonl に全halt/resumeが記録される。
  Discord: /events コマンドで最新10件を表示。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【botがオフラインのとき】
  原因候補（優先順）:
  1. Ollamaが起動していない → ollama serve を実行
  2. node_modules がない → npm install を実行
  3. .env が正しくない → DISCORD_TOKEN を確認
  4. PCが再起動されてbatが起動しなかった → 手動で node index.js

  【返答が来ない（⏳反応あり）】
  Ollamaで処理中の可能性。gemma4 は初回ロードで1〜2分かかる。
  bot_output.log を確認してエラーがないか見る。

  【観測チャンネルに何も流れない】
  1. Discord に #ai-観測 チャンネルが存在するか確認
  2. .env の OBSERVE_CHANNEL=ai-観測 を確認
  3. bot再起動後に起動ログに「観測チャンネル: #ai-観測」が出るか確認

  【Shadow Trade が記録されない】
  audit の verdict を確認（/log → audit ステップ）。
  「要見直し」の場合は設計上記録しない。

  【GitHub push が失敗する】
  1. git remote -v で origin が正しいか確認
  2. git push origin main を手動実行してエラーを確認
  3. Windows認証情報マネージャーでGitHubの認証情報を確認

  【レポートがGitHub Pagesに表示されない】
  1. reports/morning/public/ にファイルが存在するか確認
  2. git log で push されているか確認
  3. GitHub Pages の反映に最大10分かかる場合がある

  【スラッシュコマンドが出てこない】
  → node register.js を実行（数秒で反映）

  【スケジューラーが動かない】
  1. /status で trading_enabled を確認
  2. /dashboard でシステム状態を確認
  3. bot再起動後に起動ログに「スケジューラー起動完了」が出るか確認
